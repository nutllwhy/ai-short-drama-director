# AI Short Drama Director（AI 短剧导演 Skill）

一个把短剧创意或 brief 编译成可实际生成的前期制作包，并最终用一份飞书文档交付的 Codex Skill。

它先对齐剧情大纲和集尾追更钩子，再建立主角、反派、配角、系统与场景圣经，按视频平台的时长上限拆成完整生成段，制作参考素材和逐段提示词。最终成品是一份已经读回核对的飞书文档：每个生成段都能直接看到所用素材、上传顺序、时长与比例、声样、完整提示词、开始/结束状态和就绪状态，文末附完整素材包 ZIP。

当前版本：`1.0.0`

## 它解决什么问题

- 剧情只有设定，没有连续升级的冲突和下一集钩子；
- 单段切得太碎，台词断层，或超过视频模型的生成上限；
- 主配角、服装、场景和道具跨段漂移；
- 同一人物上传大量相似参考图，反而让模型混淆；
- 提示词只写动作，没有情绪、表情、说话方式和起止状态；
- 用机械 TTS 或其他角色声音冒充专属声样；
- 素材、提示词和 ZIP 散落在不同位置，交付后无法快速核对。

## 最终输出

飞书文档是唯一正式交付入口，至少包含：

1. 项目状态、比例、单段上限与声音策略；
2. 已确认大纲、冲突升级、集尾钩子和系列路线；
3. 主角、反派、常驻配角与系统实体卡；
4. 人物三视图、系统 UI、无人场景锚点及必要站位图；
5. 角色专属声样或明确的待补状态；
6. 逐生成段原生表格，显示素材预览、上传顺序、时长/比例、完整提示词和连续性状态；
7. 连续性台账、质检结果与当前阻塞项；
8. 文末当前版本完整素材包 ZIP。

文档创建成功不等于交付成功。Skill 会继续读回正文、预览图片和声样、下载并核对云端 ZIP，再生成包外 `飞书交付回执.json`。

## 工作流

```text
读取 brief 与平台限制
  → 故事契约与大纲确认门
  → 人物 / 系统 / 场景圣经
  → 最小参考图集与角色专属声样
  → 8–10 秒完整生成段
  → 逐段提示词、素材映射与连续性台账
  → 本地素材包校验
  → 飞书文档写入、读回和视觉预览
  → 云端 ZIP 下载哈希核对
  → 飞书最终交付
```

默认把“镜头”定义为一次提交给视频平台的完整生成段。段内可以有一次必要切镜，但仍使用一份按时间顺序编写的提示词；如果两个画面不能共享同一个起止状态或需要分别生成，就拆成两个生成段。

## 关键规则

- 大纲没有确认时，只交故事对齐稿，不提前生成整套人物图和提示词。
- 默认每段 `8–10 秒`，每段只完成一个可见冲突节拍，完整台词不跨段截断。
- 主角、反派和常驻具名配角各自使用人设卡、三视图和专属声样。
- 核心场景使用无人锚点；人物、可移动道具和剧情结果不烙进基础场景图。
- 每段只上传真正需要的素材。三视图负责身份，场景图负责空间，必要站位图只负责复杂关系。
- 提示词按时间顺序写清动作、镜头、情绪、表情、台词、音效和开始/结束状态。
- 默认允许环境音与动作音效，并明确写“无背景音乐”。
- 声样优先从单人角色参考视频提取并试听；待补声样不会被机械音或其他角色冒用。
- `飞书已交付`、`素材已齐` 和 `可提交视频生成` 是三个独立状态。

## 安装

### Codex

```bash
git clone https://github.com/nutllwhy/ai-short-drama-director.git
cp -R ai-short-drama-director/ai-short-drama-director ~/.codex/skills/
```

### 其他 Agent

将仓库中的 `ai-short-drama-director` 文件夹放进该 Agent 支持的 Skills 目录。

校验脚本需要 Python `3.10+`，只使用标准库。最终飞书交付需要当前环境已经连接可创建、编辑、上传媒体、插入附件、读回和预览文档的飞书/Lark 工具；缺少这些能力时必须明确标记“飞书交付阻塞”。

## 最简单的使用方式

```text
请使用 ai-short-drama-director 这个 Skill，
把下面的短剧创意先整理成一集的大纲和追更钩子。
等我确认大纲后，再完成人物、配角、场景、分镜素材和逐段提示词，
最后用一份飞书文档交付，每个分镜直接显示对应素材与提示词，文末附完整 ZIP。
```

已经有确认版大纲时，可以直接说明“大纲已确认”，并提供平台、画幅、单段时长上限和声音要求。

## 校验

```bash
python3 ai-short-drama-director/scripts/validate_drama_package.py \
  <project>/07_映射与校验/镜头与素材映射.json \
  --root <project> \
  --aspect 9:16 \
  --allow-pending-voices \
  --delivery-receipt <project>/飞书交付回执.json \
  --require-hardened-feishu-delivery
```

主要状态含义：

| 状态 | 含义 |
|---|---|
| `passed` | 本地结构、映射、文件与哈希检查通过 |
| `ready_for_document_delivery` | 已具备写入飞书文档的前期内容 |
| `delivery_verified` | 飞书正文、媒体、逐段表与当前 ZIP 已读回绑定 |
| `delivery_hardened_verified` | 逐段远端值、声样试听、视觉证据和云端 ZIP 回下载哈希均通过 |
| `ready_for_delivery` | 当前版本可以作为正式文档交付 |
| `ready_for_generation` | 所有被引用的图片和角色专属声样均已就绪，可以提交视频平台 |

允许待补声样只会让文档先交付，不会把受影响段落误标为可生成。

运行标准库 smoke tests：

```bash
python3 -m unittest discover -s ai-short-drama-director/tests -v
```

## 可见测试案例

- `花轿回头`：验证大纲未确认时不会提前制作完整素材；
- `重生在合卺酒前`：验证古装重生复仇、9 段节拍和待补声样阻塞；
- `毕业即失业，我的系统只认净利润`：验证现代男频系统流、主配角与场景资产、9×10 秒生成段和飞书唯一交付门。

公开案例只记录匿名化结构和验收结论，不包含真实飞书 token、私人声样、生产图片或客户素材。

## 如何参与迭代

欢迎通过 GitHub Issue 提交案例复盘。建议包含：题材、视频平台与模型版本、单段时长、实际提示词、问题时间码、期望保留内容和改进目标。

请不要提交保密 brief、未获授权的图片或音视频、真实声样、个人信息、私人飞书链接、文档 token、附件 token 或客户项目路径。

## 边界

- 本 Skill 负责故事设计、人物场景素材、提示词编译、生产包和飞书交付；只有用户明确要求时才操作视频生成平台。
- 平台时长、参考数量、模型能力和计费会变化，提交前应读取当前入口的实际设置。
- 结构与读回校验只能证明交付可追溯，不能替代对生成视频剧情、表演、口型、声音和连续性的逐段观看。
