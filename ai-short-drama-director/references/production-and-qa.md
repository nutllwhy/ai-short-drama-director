# 平台生成与成片验收

## 提交前读取真实平台状态

平台能力会变化。开始提交前检查当前入口的：模型名称、单次最大时长、竖横比、清晰度、编码、参考图/主体/音频数量、是否支持中文人声、是否默认加配乐、积分和并发限制。把观察到的设置写进清单，不从旧案例猜测。

若用户已经要求生成，不再为同一授权停下来确认。先补齐可逆的素材和提示词准备，再按就绪状态提交；缺关键声样的段落保留为明确阻塞。

提交任何剧情段之前，确认该段引用的人物与场景素材已在人物/场景圣经中通过检查。平台上传列表中的素材 ID、文件名和提示词中的 `@图片` / `@音频` 顺序必须完全一致。

## 提交顺序

1. 先生成并提取缺失的角色声样；试听是否自然、无机械音和背景音乐。
2. 逐镜头打开映射，只上传该平台生成段需要的图片和声样，顺序与提示词编号一致。本文中的“镜头”就是一次平台生成任务；镜头内部即使有一次必要切镜，也不拆成多个镜头 ID。
3. 检查页面实际出现的引用标签，不能只相信上传动作完成。
4. 设置时长、比例、模型和声音选项，粘贴对应镜头提示词。
5. 提交后记录任务、模型、设置和素材版本。可以并行等待独立任务，但不要在尚未确认上传绑定时批量误提。

## 成片验收

每个镜头从头到尾观看并听完，按下列顺序检查：

1. **剧情动作**：主要节拍是否真的发生，结果是否清楚；不要用时长或任务成功代替观看。
2. **开始与结束状态**：人物位置、手中物、杯量、瓶塞、门、箱子、伤势和知情状态能否与相邻段衔接。
3. **角色一致性**：脸、年龄、服装、发型、角色人数和左右位置。
4. **物理交互**：手指、持握、开合、取放、饮用、搬运和物品大小是否可能。
5. **表演**：表情与情绪是否符合台词，未说话的人是否抢口型或夸张表演。
6. **声音**：每句是否完整，声线是否属于正确角色，口型是否同步；环境音自然、无背景音乐、无额外人声。
7. **画面质量**：无多手、多指、穿模、文字乱码、现代物件和多余道具。

验收记录包含：镜头 ID、时间点、问题、保留部分、需要改变的内容、使用素材和原提示词。只重做失败的镜头；先诊断是素材、提示词、模型设置还是偶发采样，再修改最小变量。

## 状态用词

| 状态 | 可以声称什么 |
|---|---|
| draft | 大纲或脚本草案已写 |
| assets_ready | 当前段所需图片和声样都在 |
| feishu_created | 飞书文档已取得链接；正文、图片、表格或附件仍可能未完整写入 |
| feishu_verified | 新交付的飞书正文、逐镜头远端值、声样播放、视觉证据与云端 ZIP 回下载均已通过 hardened 门；这不自动表示全部镜头可生成 |
| submitted | 已在平台创建任务 |
| generated | 平台已有可播放结果 |
| inspected | 已完整观看并听完，记录了结果 |
| accepted | 满足验收标准或用户明确接受 |

不要把 ZIP、提示词、任务 ID、`ok: true`、进度 100% 或缩略图当成 `inspected` / `accepted`。

不需要的可选文件夹可以为空省略，但编号与 ID 不能因缺项重排。人物和场景基础图直接放入对应圣经目录；专属于某个镜头的站位图或结果图放入 `04_道具与分镜参考/`。`06_逐段提示词/` 是为了兼容既有 schema 保留的目录名，其中每个 `SEG##` 文件仍代表一个镜头、一次平台生成任务。README 写清项目名、比例、总时长、镜头数量、单镜头时长、版本、当前状态、待补项和飞书文档链接。`交付证据/` 与 `飞书交付回执.json` 都在 ZIP 之外；ZIP 内生产清单只描述包内素材与映射，不保存 ZIP 自身哈希。

打 ZIP 前检查：

- 文件路径、人物/场景/段落 ID 与映射表一致；
- 文件数和总大小有记录，ZIP 可以正常解压；
- 关键图片可以打开，音频可以试听；
- 清单中的哈希或版本信息对应当前文件，不把旧版素材混入；
- `待补` 项没有被误标为 ready，也没有上传空占位文件。
- ZIP 通过完整性检查，成员路径不含绝对路径或 `../`，生产清单列出的必需文件都在包内且哈希一致；
- `飞书交付回执.json` 未进入 ZIP。
- 回读证据、视觉预览证据与云端回下载 ZIP 未进入 inventory 或本地源 ZIP。

## 最终共享与验收

本 Skill 的最终交付入口是飞书文档，不把本地目录、零散图片链接或 ZIP 路径单独当作最终交付。按 [feishu-delivery.md](feishu-delivery.md) 把人物卡与人物图、场景卡与场景图、逐镜头素材提示词表和版本状态写入同一份文档，并把完整 ZIP 放在文末附件区。逐镜头表统一使用“镜头”和“时长/比例”表头。

插入表格、图片和附件后必须重新读回并预览，核对人物卡、三视图、身份图、系统 UI、场景卡、核心锚点、场景变体、已就绪声样、待补声样状态块、逐镜头表行、非空提示词、附件数、文件名与待补项。逐镜头记录远端提示词规范化 SHA-256、时长/比例、图片上传顺序和声样上传顺序；逐个播放所有已就绪声样；从文末附件回下载 ZIP 并核对 SHA-256；保存带文件路径、哈希、时间、文档 revision 与覆盖标签的视觉预览证据。全部包外证据写入 `delivery_evidence_version: 2` 回执并运行 `--require-hardened-feishu-delivery`。只有输出 `delivery_hardened_verified: true`、文档链接对用户可访问，才可以标为新版 `feishu_verified`。旧回执只允许通过 `--require-feishu-delivery` 做兼容检查。待补声样允许文档交付，但继续阻断相关视频生成镜头。
