# 来源与改造说明

本 Skill 参考了公开仓库 [nutllwhy/ai-selling-video](https://github.com/nutllwhy/ai-selling-video) 的前期制作结构，沿用了这些适合跨类型视频生产的原则：先写可复用的人设卡、人物三视图作为身份锚点、一个画面只承担一个分镜内容、物理交互与肢体检查、台词和时长匹配、无背景音乐，以及把每段实际使用的素材与完整提示词放进同一张对照表。人物图不是装饰；它必须在后续分镜中以明确 ID 被引用。

短剧与带货视频的核心问题不同，因此本 Skill 重新设计了故事层：先由用户确认剧情大纲；确认前不生成素材；确认后为主角、反派、常驻具名配角建立完整人设卡与三视图，为一次性具名配角建立身份图，为出镜场景建立无人锚点或变体参考；现代系统流另建系统实体卡、UI 锚点和独立声样；用“目标—阻力—动作—结果—控制权”检查每段转折；维护人物、道具和信息状态；让集尾危机来自反派对本集结果的反应；按角色建立真实视频提取声样。带货 Skill 中的固定品类、五类商品画面、商品卖点和 3–5 秒节奏没有移植到短剧。

飞书文档唯一交付入口、独立机器可读故事契约、文内人物/场景/声样状态、逐段素材提示词表、文末 ZIP 附件以及创建后的读回/预览/分类计数验收，是针对本短剧生产流程增加的交付规范。ZIP 内生产清单与 ZIP 外飞书交付回执分开，避免 ZIP 自哈希循环，并把文档 revision、媒体块、分段行和附件 token 绑定到当前版本。它借鉴“素材和提示词同处一张表”的可读性原则，但不把带货主播、商品图或 A-roll/B-roll 分类硬套到剧情短剧。
