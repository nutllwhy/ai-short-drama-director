# 飞书文档交付

完整前期包完成后，用一份飞书文档作为唯一交付入口。文档负责浏览和审阅，ZIP 负责完整下载；本地目录仍是制作源，但最终回复不要让用户在多个本地路径、图片和表格之间拼接结果。

本文中的“镜头”与“生成段”同义，指一次平台生成任务。一个 8–10 秒镜头内可以有一次必要切镜，但仍共用一个镜头 ID、一套上传顺序和一份完整提示词；只有另起一次生成任务时才拆出新的镜头行。

若当前环境有飞书文档 Skill，先读取其创建、表格、图片、附件与读回说明，再执行。本文件定义内容和验收要求，不替代具体工具参数。若飞书权限、登录或上传能力受阻，保留已完成的本地包并明确标为“飞书交付阻塞”，不能用“本地已完成”代替“飞书已交付”。

## 文档标题与版本

标题使用：

```text
《项目名》｜AI短剧完整制作包｜v001
```

文档开头保留一个状态区：

| 字段 | 内容 |
|---|---|
| 项目 | 剧名 / 集数 |
| 当前版本 | v001 与日期 |
| 画面规格 | 比例、总时长、生成段数量、单段时长 |
| 故事状态 | 大纲已确认 / 待确认 |
| 素材状态 | 人物图、场景图、已就绪声样、待补声样分别计数 |
| 生成状态 | draft / assets_ready / submitted / generated / inspected / accepted |
| 本版变更 | 相对上一版的具体变化 |

只有大纲已确认后才创建“完整制作包”文档。大纲门阶段可以分享单独的“大纲对齐稿”，但不得在其中伪装完整人物、场景或分镜素材已经完成。

## 创建顺序

生产清单只记录包内内容；飞书读回和当前 ZIP 的哈希写入包外 `飞书交付回执.json`。这样 ZIP 不需要包含自己的哈希，也不会因更新读回信息而改变。按以下顺序执行：

1. 本地素材与映射完成后，先创建飞书文档空壳，取得最终文档链接；
2. 把该链接和当前版本写入本地 `README.md` / 版本说明；
3. 完成包内生产清单，生成并校验当前版 ZIP；ZIP 内不得放 `飞书交付回执.json`；
4. 写入文档正文，上传人物图、场景图和逐镜头表素材；
5. 在文末上传刚校验的 ZIP；
6. 读回文档，逐镜头提取远端提示词、时长/比例、图片和声样上传顺序；对远端提示词按 `sha256:utf8-nfc-lf-strip-v1` 计算哈希，并绑定表格行与提示词容器 ID；
7. 逐个播放全部 `ready: true` 声样，记录块 ID、媒体 token、时长、试听时间以及可听、角色正确、自然、无背景音乐四项结果；待补声样绑定状态块与原因；
8. 从文末附件入口回下载当前 ZIP 到独立的包外证据路径，核对附件 token、大小、SHA-256 与本地源 ZIP 完全一致；
9. 打开视觉预览，保存 PNG、JPEG、WebP 或 PDF 证据，记录路径、大小、SHA-256、时间、文档 revision 和覆盖范围；覆盖范围至少包括文档头、全部人物、场景、图片、声样、镜头行和附件区；
10. 在项目根目录写入包外 `飞书交付回执.json`，使用 `delivery_evidence_version: 2`，并把上述远端读回、播放、回下载和视觉证据同步写入独立回读证据 JSON；
11. 用 `--require-hardened-feishu-delivery --delivery-receipt 飞书交付回执.json` 运行最终交付门；
12. 如修复内容会改变 ZIP 内文件，重建 ZIP、替换文末附件、重新读回、重新播放受影响声样、重新回下载并覆盖证据，不能沿用旧哈希或旧附件证据。

## 文档结构

按以下顺序组织，便于先看故事，再核对素材，最后逐镜头生产：

1. **项目状态与使用说明**
   - 规格、版本、生成平台假设、待补项；
   - 明确三视图、身份图、无人场景和站位图各自用途。
2. **已确认剧情大纲**
   - 一句话故事、故事契约、逐拍大纲、本集实赢、集尾钩子；
   - 标出用户确认日期或确认依据；文内角色、核心场景、分段和比例必须与包内 `01_剧情/故事契约.json` 一致。
3. **人物圣经**
   - 主角、反派、常驻具名配角、一次性具名配角依次排列；
   - 每人先放人设卡，再把对应三视图或身份图直接内嵌在卡片下方；有对白且声样已就绪时紧邻放角色专属声样的可播放音频块或附件块，尚未授权生成或待补时放明确状态块与受影响段落；
   - 图片标题写素材 ID、文件名和用途，例如 `CH01｜林野三视图｜只锁身份与常驻服装`。
   - 非实体系统单列“系统实体卡”；展示规则、声样状态和系统 UI 锚点，不伪造人物三视图。
4. **场景圣经**
   - 每个生成场景先放场景卡，再内嵌对应无人图；核心场景使用 `scene_anchor`，次要场景和明显变体使用 `scene_variant`；
   - 图片标题写场景 ID、文件名、固定空间和禁止继承的可变物件。
5. **完整脚本与连续性**
   - 逐段列剧情动作、对白、情绪与表情、开始状态、结束状态；
   - 单列关键道具、人物位置、已知信息与跨段承接。
6. **逐镜头素材与提示词表**
   - 使用飞书原生表格，不用截图或只贴外链；
   - 每个生成段占一行，完整提示词必须可直接复制。
7. **素材状态与校验**
   - 人物、场景、道具、声样、分镜参考的 ready / 待补清单；
   - 本地校验结果、当前不能提交的段落和原因。
8. **完整素材包下载**
   - 文末上传当前版本 ZIP 附件；
   - 写明 ZIP 文件名、版本、大小、文件数、生成时间和校验值；
   - 旧版附件移入“历史版本”或明确标旧，不能与当前版本并列而无说明。

## 人物与场景区块

人物卡、人物图和角色声样状态必须同处一个区块，不要把所有图片或音频堆到文末。主角、反派和常驻具名配角各自至少显示一张三视图；一次性具名配角显示身份图；有对白角色显示自己的可播放声样块/附件块，或明确的待补状态块。场景卡下直接显示对应无人锚点。飞书中只引用云端已上传的媒体，不插入仅本机可见的绝对路径。

人物卡建议用两列表格：

| 项目 | 内容 |
|---|---|
| 身份与叙事功能 | … |
| 面部/体态锚点 | … |
| 发型、妆面与服装 | … |
| 关系、利益与表演基线 | … |
| 声线与声样状态 | … |
| 禁止漂移 | … |

场景卡建议用两列表格：

| 项目 | 内容 |
|---|---|
| 剧情功能 | … |
| 时代、地点、时段 | … |
| 空间结构与方位 | … |
| 固定家具与光线 | … |
| 可变道具 | … |
| 禁止漂移 | … |

图片上传后打开预览，确认没有被错误裁切到看不清三视图、人物脸或场景结构。必要时拆成更合适的展示尺寸，但不要重复上传相近图凑数量。

## 逐镜头素材与提示词表

每一行对应一个真实的平台生成任务：

| 镜头 | 局面变化 | 时长/比例 | 素材图预览 | 图片素材（按上传顺序） | 声样（按上传顺序） | 完整生成提示词 | 开始→结束状态 | 就绪状态 |
|---|---|---|---|---|---|---|---|---|

填写规则：

- “时长/比例”写平台实际选择值，例如 `10秒｜9:16`，不只写剧情时间码；
- “素材图预览”直接内嵌该段实际使用的人物、场景、道具或站位图；复用同一基础图时沿用原素材 ID，不重新生成近似图片；
- “图片素材”写 ID、文件名和用途，例如 `① CH01_三视图.png：锁主角身份；② SC02_无人锚点.png：锁后台空间`；
- “声样”写角色 ID、文件名与“只参考音色”，缺失时写 `待补，禁止提交`；
- “完整生成提示词”保留设置、参考映射、开始状态、可见行动、对白与表演、音效、无背景音乐和结束状态，不能写“见附件”“同上”；
- “就绪状态”只在该行全部图片、声样和提示词可用时标 `ready`；
- 若飞书表格单元格无法舒适展示长提示词，在该行紧邻位置追加唯一对应的可复制代码块，表格提示词列写同一段落 ID 与跳转标识；这是正式降级方式。读回时，一个完整单元格或一个紧邻代码块都计为一份提示词，每段必须恰好一份，不能把素材与提示词拆成互不关联的两套编号。

表格前放一个素材图例，展示全部人物三视图、具名配角身份图、系统 UI 锚点和全部生成场景的无人参考图。逐段表同时在每行直接展示对应素材缩略图并保留 ID 与上传顺序，形成“视频段—素材图—提示词”的单行对照；专用站位图或结果图也放在对应行，并在素材包保留原文件。若工具不支持在表格单元格内放图，就在该数据行紧邻的下一块按相同段落 ID 插图，不能把图片集中到另一个无段落映射的图片区。

## ZIP 附件

ZIP 使用和文档一致的版本名，例如：

```text
项目名_AI短剧完整制作包_v001.zip
```

上传前确认可以解压，人物、场景、声样、提示词、映射和校验文件齐全。ZIP 内包含生产清单，不包含包外 `飞书交付回执.json`。文末附件说明至少包含：

```text
附件：项目名_AI短剧完整制作包_v001.zip
版本：v001
文件数：__
大小：__
SHA-256：__
包含：剧情、人物圣经、场景圣经、道具与分镜参考、声样、逐段提示词、映射与校验
```

飞书附件上传成功的标准是：文档读回时能看到附件块、文件名与大小，取得附件 token，并从该入口实际回下载一份独立证据文件；回下载文件的大小和 SHA-256 必须与本地当前 ZIP 完全一致。只获得本地 ZIP、上传接口成功响应或相同云端大小都不算附件已交付。

## 包外交付回执

`飞书交付回执.json` 是执行飞书写入、读回、声音播放、附件回下载和视觉预览后生成的本地证据，不能预填，也不能打进被它校验的 ZIP。新交付使用 `delivery_evidence_version: 2` 和 `prompt_hash_profile: sha256:utf8-nfc-lf-strip-v1`，至少记录：

- `document_url`、`document_id` 与 URL 中一致的文档 token；
- 带时区的 `verified_at`、本轮 `readback_evidence_id` 和 `revision`；
- 人物卡、三视图、身份图、系统 UI、场景卡、核心锚点、场景变体、已就绪声样、待补声样、逐段表行、完整提示词和附件的分类实见数量；
- 每个图片素材 ID 对应的图片块/媒体 token、每个已就绪声样 ID 对应的音频块/附件 token、每个待补声样 ID 对应的状态块 ID、每个分段 ID 对应的表格行 ID；
- `segment_readback`：每个镜头的 `row_id`、`prompt_block_id`、远端完整提示词规范化 SHA-256、`duration_seconds`、`aspect_ratio`、`image_upload_order` 和 `voice_upload_order`；这些值必须逐项等于 manifest；
- `voice_playback_verification`：每个已就绪声样的播放块、媒体 token、试听时间、实际时长和四项试听结果；每个待补声样的状态块与原因；`previewed_voice_ids` 只列已实际播放的 ready 声样；
- `visual_preview_evidence`：包外 PNG、JPEG、WebP 或 PDF 的路径、大小、SHA-256、截图时间、文档 ID、revision 和覆盖标签；
- 当前附件 `attachment_token`、文件名和 `cloud_size_bytes`，以及 `current_archive.cloud_download` 中独立回下载 ZIP 的路径、下载时间、token、大小与 SHA-256；
- 本地当前 ZIP 的文件名、大小、SHA-256 和包内文件数。回下载 ZIP 必须与本地源 ZIP 哈希一致，两个文件不能使用同一路径。

回执引用的独立回读证据 JSON 必须包含：与回执一致的 `delivery_evidence_version`、`prompt_hash_profile`、`document_id`、`readback_evidence_id` 和 `revision`；12 项分类计数；完整的图片、声样和镜头块绑定；与回执逐项相同的 `segment_readback`、`voice_playback_verification`、`visual_preview_evidence` 与 `cloud_archive_download`。提示词哈希的规范化顺序固定为 Unicode NFC、CRLF/CR 转 LF、首尾 `strip()`、UTF-8 SHA-256。不得复制旧项目、旧版本或手写虚构的 token、计数和时间。

`交付证据/`、回读证据 JSON、视觉预览证据、云端回下载 ZIP 与项目根 `飞书交付回执.json` 都属于包外证据，不进入 inventory 或素材 ZIP。旧回执缺省按 evidence v1 处理，只能通过兼容的 `--require-feishu-delivery`；新交付必须通过 `--require-hardened-feishu-delivery`，输出 `delivery_hardened_verified: true`。

## 创建后的读回验收

创建文档后执行一次内容读回和一次视觉预览。先从本地清单计算预期数量，再与文档实见数量对照：

| 验收项 | 预期 | 实见 | 结果 |
|---|---:|---:|---|
| 人物卡 | 主角+反派+全部具名配角数 | 读回计数 | pass / fail |
| 三视图 | 主角+反派+常驻具名配角数 | 预览计数 | pass / fail |
| 一次性配角身份图 | 一次性具名配角数 | 预览计数 | pass / fail |
| 场景卡 | 全部生成场景数 | 读回计数 | pass / fail |
| 无人场景图 | 核心锚点+次要/变体参考数 | 预览计数 | pass / fail |
| 已就绪角色声样 | `ready: true` 声样数 | 可播放音频/附件块计数 | pass / fail |
| 已播放声样 | `ready: true` 声样 ID 集合 | 逐个播放记录与媒体 token | pass / fail |
| 待补角色声样 | `ready: false` 声样数 | 待补状态块计数 | pass / fail |
| 逐镜头表数据行 | 生成段数 | 表格数据行数 | pass / fail |
| 远端完整提示词 | 生成段数 | 规范化 hash 与本地 prompt 相同 | pass / fail |
| 时长/比例与上传顺序 | 全部生成段 | 逐镜头远端值与 manifest 相同 | pass / fail |
| 当前版 ZIP | 1 | 可见附件且回下载 hash 与本地 ZIP 相同 | pass / fail |
| 视觉预览证据 | 1 组 | 包外证据覆盖全部必需标签 | pass / fail |

读回检查内容：标题与版本正确；表格没有少行、错列或被截断；每镜头远端时长、比例、图片顺序、声样顺序和提示词 hash 与 manifest 一致；所有图片实际显示；已就绪声样逐个播放通过；待补项可见；文末 ZIP 文件名、版本和回下载 hash 正确。

视觉预览检查：人物三视图能看清全身和三个角度；场景锚点能看清空间；宽表可横向查看或按段落拆成可读表格；长提示词可复制；附件位于文末且不会被误认为旧版。

任一计数、hash、顺序、播放结果或视觉覆盖不一致时，补写或重传后重新取证，不沿用上一次成功响应。读回、声音播放、附件回下载与视觉预览通过后，写包外交付回执并运行 hardened 最终交付门；`delivery_hardened_verified: true` 后才能标记新版 `feishu_verified`。最终回复只给这份飞书文档链接，并简要说明当前版本和待补项；ZIP 通过文末附件取得，不再要求用户从聊天中逐个下载素材。
