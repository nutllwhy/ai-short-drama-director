# 故事大纲与冲突设计

## 大纲门：先写故事契约

大纲尚未得到用户明确认可时，只做故事层决策。可以列角色姓名、身份、利益关系和核心场景，但不要写制作级人物卡，不要生成三视图、身份图、场景图、声样、逐段提示词或 ZIP。用户确认核心故事后，才进入人物与场景圣经；这条门槛不因时间紧或用户要求“直接做案例”而跳过，除非用户已经提供了明确的确认版大纲。

在详细台词和镜头前，用一页以内锁定以下内容：

| 字段 | 要回答的问题 |
|---|---|
| 主角 | 主角现在要拿回、保住或达成什么？ |
| 反派 | 他正在实施什么具体计划？ |
| 时限 | 为什么必须在这一集、这一场或今晚行动？ |
| 主角优势 | 重生记忆、证据、身份、盟友或技能中，哪一项能改变局面？ |
| 代价 | 失败会失去什么？成功又会触发什么反噬？ |
| 本集实赢 | 结尾前主角实际拿到什么，不是只说了一句狠话？ |
| 下一集危机 | 谁因本集结果采取了什么新行动？ |

若题材是重生复仇，先回答“重生时点”和“前世亲眼所见”。主角只能利用已经经历或当场查到的信息，不能凭作者视角知道隐藏事实。

## 用局面变化判断信息密度

每个段落写一行转折台账：

| 段 | 主角当下目标 | 对手阻力 | 主角动作 | 可见结果 | 谁掌控局面 |
|---|---|---|---|---|---|

满足下列任一项才算有效转折：

- 新证据改变了可信判断；
- 原计划失败，人物被迫换策略；
- 同盟破裂、站队改变或人物暴露；
- 道具、证人、财物或行动权实际转手；
- 角色公开作出不可轻易撤回的选择；
- 上一段的行动引发新危险。

两段连续只有解释、回忆或对话确认时，合并或让其中一段发生可见结果。高密度不等于每个人都喊话；控制权变化比台词数量更重要。

## 一集的推荐形状

这不是固定公式，可按用户题材调整：

1. 冷开场给出代价或秘密，让观众立刻知道主角为什么必须反击。
2. 主角获得第二次机会或发现异常，明确本集目标。
3. 主角先出一招，迫使反派暴露或应对。
4. 第一招受阻，证据被毁、盟友背叛或计划出现缺口。
5. 主角换策略，抓住更具体的证据、证人或资源。
6. 反派切割同盟或发动压制，冲突升级。
7. 共犯互咬、身份翻转或关键真相公开。
8. 主角得到一项可验证成果，例如退婚、带走财物、救出证人或拿到命令。
9. 反派因失败采取更狠但合乎逻辑的行动，留下下一集危险。

一个 60–90 秒的高密度首集，通常每 1–2 个生成段至少改变一次目标、证据、联盟、控制权或危险等级。不要为了凑反转加入与人物利益无关的偶然事件。

## 因果审计

写完大纲后逐项检查：

- 道具从哪里来，何时被看见，为什么此刻在这个人手里？
- 证据能证明什么、不能证明什么？可疑行为不要写成科学鉴定。
- 反派为什么拒绝、毁证、甩锅或追杀？他的动作是否维护自己的利益？
- 共犯为什么此刻背叛？恐惧、自保、嫉妒或利益必须有当场触发。
- 主角赢得的财物、证人或身份是否真的还在她控制中？
- 结尾危机是否由本集行动触发，还是凭空出现？
- 前后时间、空间和人群是否允许这一动作发生？

## 大纲对齐格式

用户尚未确认故事时，先交付：

1. 一句话故事；
2. 主要角色和利益关系；
3. 逐段或逐拍剧情大纲；
4. 本集实赢与下一集钩子；
5. 最容易失真的两到三个因果点。

只确认会改变整条故事线的选择。用户认可后，把这版大纲视为故事契约；后续若需改核心关系、凶手、结局或时代，应先指出变化而不是暗中重写。

## 确认后的制作交接

大纲获批后，把以下内容交给人物与场景圣经，不再凭分镜临时补设定：

- 角色清单：主角、反派、常驻具名配角、一次性具名配角、非实体系统 / 器灵 / 画外人格、无名群演；
- 每人的叙事功能、关系、首次出现段落、是否开口、是否跨集复用；
- 核心场景清单：会重复出现、承担关键动作或需要跨段保持空间关系的地点；
- 每个场景的时代、时段、固定结构、入口出口、主要光源和关键固定家具；
- 已经锁定且不能随意改变的身份、时代、妆造、场景与道具条件。
- 将确认版大纲另行编译为 `01_剧情/故事契约.json`：记录并命名全部具名角色/系统实体 ID、核心场景 ID、生成段 ID、比例、确认版大纲文件与哈希、确认时间和确认依据。生产清单只能引用并复核这份独立契约；后续不能通过删掉角色或场景并同步缩小生产清单来绕过故事契约。核心关系或规模变化时，先取得用户认可，再生成新版本故事契约。

随后按 [character-scene-bible.md](character-scene-bible.md) 制作人设卡、人物图和无人场景锚点。剧情角色清单不等于制作素材完成；只有对应卡片和图像通过检查后，才能标记相关素材就绪。
